# Crucible

> Where raw ideas survive the heat.

Crucible is a Claude Code skill that turns a raw idea into a fully designed project: brand identity, visual design system, logo system, and tech stack, with every decision shown in your browser.

![Brand preview page generated by Crucible](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase6-preview-top.png)

You describe an idea in the terminal. Crucible asks one question at a time, and every choice opens as a page in your browser, so you decide by seeing, not by reading a list. At the end you have a complete design package in `docs/crucible/`.

## Install

Crucible is a single `SKILL.md`. Clone it into your Claude Code skills folder:

```bash
# available in every project
git clone --depth 1 https://github.com/johnivanpuayap/crucible ~/.claude/skills/crucible

# or just this project
git clone --depth 1 https://github.com/johnivanpuayap/crucible .claude/skills/crucible
```

Or, if you use the [skills CLI](https://skills.sh):

```bash
npx skills add johnivanpuayap/crucible
```

**Requirements**

- [Claude Code](https://claude.com/claude-code)
- [`superpowers`](https://github.com/obra/superpowers) — Phase 1 runs its `brainstorming` skill for concept exploration and the design spec
- [`ui-ux-pro-max`](https://github.com/nextlevelbuilder/ui-ux-pro-max-skill) (optional) — if installed, its design-system suggestions become options in Phase 3; if not, Crucible generates its own

## Usage

Start Claude Code in your project and describe the idea:

```
/crucible I run a badminton open-play group. Who plays next is decided on a whiteboard,
so some people wait forever, matches are lopsided, and the gym has no signal.
```

Crucible then walks you through six phases, one question at a time. Say the letter of the option you want, ask for tweaks, or ask for another round.

To skip the conversation, give a detailed brief and ask for one-shot mode:

```
/crucible just generate it: a badminton open-play queue app for organizers, offline-first PWA,
casual and friendly tone, teal and yellow, React + Firebase.
```

If `docs/crucible/` already exists, Crucible asks whether to start fresh or redo specific phases.

## What It Does

1. **Concept Exploration** — What's the idea, who's it for, what problem does it solve
2. **Brand Identity** — Name, tagline, tone of voice, personality
3. **Visual Identity** — Color palette, typography, UI style
4. **Logo System** — SVG logo, app icon, wordmark, favicon, with usage guidelines
5. **Tech Stack** — Best-fit recommendation with rationale
6. **Output** — Markdown docs, decision pages, logos, and a visual brand preview

## A Full Run, In Pictures

The pictures below follow one project through every phase: **Sunod**, a badminton open-play queue app for organizers. Everything shown here is what Crucible writes to `docs/crucible/` during an interactive run.

### Start

Invoke `/crucible` with your idea. Crucible explains the phases and starts asking questions.

![Starting Crucible in the terminal](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/terminal-start.png)

### Phase 1 — Concept Exploration

Crucible hands the idea to the `brainstorming` skill. Each clarifying question with options opens as a decision page with trade-offs side by side, and the recommended option is marked. The answers become the design spec in `specs/`.

![Phase 1 decision page: form factor](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase1-form-factor.png)

### Phase 2 — Brand Identity

**2a. Name.** Candidates are shown where they will live: the home screen icon, the app header, and the splash screen.

![Phase 2a decision page: names](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase2a-names.png)

**2b. Tagline.** Each tagline is placed on the splash screen and as the app-store subtitle.

![Phase 2b decision page: taglines](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase2b-taglines.png)

**2c/2d. Tone of voice and personality.** The same screen three times, with only the copy changing. The chosen option sets the voice for every label and error message, and is written to `brand.md` together with the personality attributes.

![Phase 2c decision page: tone of voice](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase2c-tone.png)

### Phase 3 — Visual Identity

**3a. Color palette.** Three color directions applied to a mock of the product's main screen. Every page from here on has a light/dark toggle. If `ui-ux-pro-max` is installed, its suggestion is one of the options.

**3b. Typography.** Font pairings from Google Fonts rendered on the real screen, in the chosen palette.

![Phase 3b decision page: typography](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase3b-typography.png)

**3c. UI style.** Surfaces, radius, shadows, and motion, compared on the same screen. Palette, fonts, and style land in `design.md`.

![Phase 3c decision page: UI style](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase3c-ui-style.png)

### Phase 4 — Logo System

**4a. Logo type and style.** Combination mark, lettermark, pictorial mark, or wordmark, each sketched with the brand's own name and colors. Then the visual style within the chosen type.

![Phase 4a decision page: logo type](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase4a-logo-type.png)

![Phase 4a decision page: logo style](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase4a-logo-style.png)

**4b. Concepts.** Three logo concepts as real SVG, each with its design rationale, shown in light and dark, in monochrome, in the app header, and as an icon from 160px down to a 16px browser tab.

![Phase 4b decision page: logo concepts](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase4b-logo-concepts.png)

**4c. Full logo system.** From the chosen concept, Crucible generates the primary logo, wordmark, app icon, and favicon, each in full color, monochrome dark, and monochrome light, plus `USAGE.md`. The review page shows the actual files from `logos/`.

![Phase 4c page: generated logo system](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase4c-logo-system.png)

If you'd rather not generate logos, Crucible writes a logo brief into `brand.md` instead: three described concepts a designer or image tool can execute later.

### Phase 5 — Tech Stack

Realistic stack options scored against what the project actually needs, with an architecture diagram for the recommendation. The choice and its rationale go to `tech-stack.md`.

![Phase 5 decision page: tech stack](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase5-tech-stack.png)

### Phase 6 — Output

Crucible writes every artifact to `docs/crucible/`, commits them, and offers a visual preview.

![Finishing Crucible in the terminal](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/terminal-finish.png)

The preview is a single `preview.html` that pulls the whole brand together: logo system, light and dark palettes, typography, sample screens, UI components, voice, and tech stack. The top of it is the image at the start of this README; [see the full page](https://raw.githubusercontent.com/johnivanpuayap/crucible/assets/images/phase6-preview.png).

### Phase 7 — Push to Tracker (optional)

If `~/.crucible/config.json` exists, the generated files are uploaded to your tracker. If it doesn't, nothing happens and the run is complete. See [Optional Integration](#optional-integration).

## Output

```
docs/crucible/
├── specs/YYYY-MM-DD-<topic>-design.md   # Full design spec
├── plans/YYYY-MM-DD-<plan-name>.md      # Implementation plan
├── brand.md                              # Name, tagline, tone, personality, logo notes
├── design.md                             # Palette (light + dark), typography, UI style
├── tech-stack.md                         # Recommended stack + rationale
├── decisions/                            # HTML decision pages, one per choice point
│   └── NN-<phase>-<topic>.html           #   chosen option marked on each page
├── logos/                                # SVG logo system + USAGE.md
└── preview.html                          # Visual brand preview
```

Every file is plain Markdown, HTML, or SVG. Nothing depends on Crucible after the run.

## Modes

- **Interactive (default)** — Guided conversation, one question at a time, every decision shown in the browser
- **One-shot** — Describe everything upfront, get the full package. Decision pages are skipped and `preview.html` covers the visual review; logos come as a brief unless you ask for SVGs

## Optional Integration

Crucible can push generated files to a tracker app (like [Canopy](https://github.com/johnivanpuayap/canopy)) via API. Create `~/.crucible/config.json`:

```json
{
  "api_url": "https://your-app.vercel.app/api",
  "api_key": "your-api-key",
  "user_id": "your-user-id"
}
```

Without this file Crucible works fully standalone and never mentions the tracker.
